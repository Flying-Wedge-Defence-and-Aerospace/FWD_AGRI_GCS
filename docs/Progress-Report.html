1. Project Overview

FWDAgriGCS is a custom fork of QGroundControl, developed as a ground control station for Flying Wedge Defence AI's agricultural drone fleet. The application runs on both Linux (AppImage) and Android (APK) platforms.

Objective: Implement an in-app auto-update system that checks GitHub Releases on startup, shows an update dialog with changelog, and downloads & installs updates automatically on both platforms. Additionally, set up a GitHub Actions CI/CD pipeline to automatically build and release Linux AppImage and Android APK when a version tag is pushed.

3. CI/CD Pipeline — Completed

A GitHub Actions workflow was created to automatically build both Linux AppImage and Android APK, create a GitHub Release, and upload binaries when a version tag is pushed.

3.1 Workflow Architecture

JobRunnerPurpose
linux-buildubuntu-22.04Build Qt desktop, create AppImage
android-buildubuntu-22.04Build Qt Android, create & sign APK
releaseubuntu-22.04Download artifacts, create GitHub Release with binaries

3.2 What the Pipeline Does

  1. On git push with a v* tag, triggers the workflow
  2. Linux job: Installs Qt 5.15.2 + dependencies → qmake → make → Creates AppDir with full Qt directory → Builds AppImage with appimagetool
  3. Android job: Installs Qt 5.15.2 Android + JDK 17 (SDK) + JDK 11 (Gradle) + Android NDK → qmake → make → androiddeployqt → Injects AndroidX properties → Runs gradle assembleRelease → Signs APK with debug keystore
  4. Release job: Downloads both artifacts → Creates GitHub Release tagged with the version → Attaches AppImage and APK

3.3 Key Technical Decisions

DecisionReason
JDK 17 for SDK tools, JDK 11 for GradleAndroid SDK cmdline-tools 16.0 requires JDK 17, but Gradle 5.6.4 requires JDK 11
aqtinstall arch = "android" not "android_arm64_v8a"Qt 5.15.2 aqtinstall naming convention
aqtinstall module = "qtcharts" not "charts"Qt Charts module name in aqtinstall
OpenSSL 3.0 pragma in FWDCertVerifier.ccUbuntu 22.04 runner uses OpenSSL 3.0 which deprecates EC_KEY APIs
androiddeployqt with continue-on-error + manual gradleandroiddeployqt overwrites gradle.properties, removing AndroidX flag
Soft-sign APK with debug keystoreAPK must be signed to install on Android; debug keystore is sufficient for testing

5. Known Issues & Pending Fixes

Status at time of report: The CI pipeline has been iteratively debugged through 19 test tags (v1.0.11-test through v1.0.11-test19). Linux AppImage and Android APK builds have been individually advanced to near-completion. A couple of issues remain before both builds pass cleanly.

5.1 AppImage — AppRun File Not Generated by Build

PENDING

DetailDescription
ProblemThe AppRun file in the staging directory is a manually created artifact. It is NOT generated by make or qmake. On a fresh CI runner it does not exist, causing cp: cannot stat 'AppRun'.
Planned FixGenerate AppRun inline in the workflow using a heredoc, while still copying the full Qt directory and supporting files from staging.
StatusFix identified, awaiting implementation in next CI test.

5.2 AppImage — OpenSSL Library Bundling

FIXED IN TEST17

DetailDescription
ProblemBinary links against libcrypto.so.3 (OpenSSL 3.0 on Ubuntu 22.04 runner), but it was not included in the AppImage.
FixCopy the full Qt/ directory from staging (which contains all bundled libs) instead of individually copying system OpenSSL.

5.3 AppImage — Missing Qt Plugins & QML

FIXED IN TEST18

DetailDescription
ProblemEarlier workflow only copied Qt/libs/ but not Qt/plugins/ or Qt/qml/, causing runtime failures.
FixCopy entire Qt/ directory: cp -rL Qt AppDir/

5.4 Android — Gradle AndroidX Error

PENDING

DetailDescription
Problemandroiddeployqt generates its own gradle.properties from Qt's template, overwriting any pre-existing file. The template lacks android.useAndroidX=true. Our approach of injecting after androiddeployqt (with continue-on-error: true) then running gradle manually was implemented but may still fail because the generated gradle.properties also lacks other required properties like qt5AndroidDir.
Planned FixInstead of overwriting gradle.properties, append only the AndroidX properties to the file that androiddeployqt generates. This preserves Qt-generated properties (qt5AndroidDir, androidCompileSdkVersion, etc.) while adding AndroidX support.
StatusFix pushed in commit 107fa22 (test19) — appends instead of overwrites. Awaiting test result.

5.5 Android — JDK Version Split

FIXED IN TEST14

DetailDescription
ProblemAndroid SDK cmdline-tools 16.0 requires JDK 17, but Gradle 5.6.4 requires JDK 11.
FixInstall JDK 17 for SDK setup, then switch to JDK 11 for gradle build steps.
